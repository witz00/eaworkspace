# Страница кейса внутри раздела «Проекты»

## Цель
При клике на карточку кейса в разделе «Проекты» показывать отдельный вид — страницу кейса — вместо модального окна (модалка ранее была удалена). Правый контейнер (`.card-right`) и левое меню не меняются структурно; вид переключается только внутри содержимого раздела «Проекты».

## Архитектура
`renderProjects(container)` (в `src/sections/projects.js`) управляет двумя внутренними видами через замыкание:
- **Grid view** — текущая сетка карточек (`.proj-grid-card`).
- **Case view** — страница отдельного кейса.

Оба вида рендерятся в один и тот же `container` через полную замену `container.innerHTML` и повторное навешивание обработчиков после каждого рендера (аналогично текущему подходу, где `renderProjects` уже переписывает `container.innerHTML` целиком).

Никаких изменений в `main.js`, nav, breadcrumb вне раздела «Проекты» не требуется — левое меню (`.card-left`) остаётся видимым и активным как обычно, `.card-right` не меняет размеры/позицию.

## Переход в деталь кейса
Клик по `.proj-grid-card[data-index="i"]` → рендерит case view для `cases[i]`.

## Case view — разметка
Вместо `<span class="section-label">Проекты</span>` (используется только в grid view) — breadcrumb:

```html
<div class="content-area">
  <div class="proj-crumb">
    <button class="proj-crumb-link" data-nav="grid">Проекты</button>
    <span class="proj-crumb-sep">/</span>
    <button class="proj-crumb-link" data-nav="grid">Кейс 1</button>
  </div>
  <div class="proj-case-body">
    <p>В разработке</p>
  </div>
</div>
```

- Текст последнего звена breadcrumb берётся из `cases[i].company` (например, `Кейс 1`, `Кейс 2`).
- **Оба звена кликабельны** и оба ведут обратно в grid view (клик на любое — рендерит сетку заново).
- Тело кейса показывает текст-заглушку «В разработке» — то же самое, что уже используется для карточек в сетке (`cases[i].title === 'В разработке'`).

## Возврат в сетку
Клик по `.proj-crumb-link` (любому из двух) → рендерит grid view заново (тот же `container.innerHTML`, что рендерится при инициализации `renderProjects`).

## Стили (`src/style.css`)
Добавить рядом с существующими стилями `.proj-*` (после блока `/* ── Projects grid ── */`):

```css
.proj-crumb {
  display: flex;
  align-items: center;
  gap: 8px;
}

.proj-crumb-link {
  background: none;
  border: none;
  padding: 0;
  font-size: 24px;
  font-weight: 400;
  color: var(--dim);
  cursor: pointer;
  transition: color 0.2s;
}

.proj-crumb-link:last-child { color: var(--white); }
.proj-crumb-link:hover { color: var(--white); }

.proj-crumb-sep {
  font-size: 24px;
  color: var(--dim);
}

.proj-case-body {
  font-size: 18px;
  color: var(--body-text);
}
```

Последнее звено breadcrumb (текущая страница) визуально выделено (`var(--white)`) сразу при рендере — не только по hover, — чтобы было понятно, что это активная страница, даже если оно тоже кликабельно.

## Данные
Используется существующий массив `cases` в `src/sections/projects.js` — новых полей не требуется, `cases[i].company` уже содержит нужное имя («Кейс 1», «Кейс 2»).

## Что не меняется
- Карточки в сетке (`.proj-grid-card`) остаются пустыми `div` без текста/изображения — визуально не меняются, только становится реальным клик-переход вместо (уже удалённой) модалки.
- `.card-right`, `.card-left`, `main.js` — без изменений.
- Мобильная адаптация: breadcrumb использует те же принципы, что и `.section-label` на мобильном (уменьшенный шрифт) — добавить `.proj-crumb-link`/`.proj-crumb-sep` в существующий мобильный блок с уменьшенным `font-size`, аналогично `.section-label { font-size: 15px }`.

## Тестирование
Ручная проверка в браузере: клик по карточке → показывается breadcrumb + «В разработке»; клик по любому из двух звеньев breadcrumb → возврат в сетку; переключение между разделами меню (Знакомство/Опыт/Коммуникация) во время открытой страницы кейса корректно сбрасывает/восстанавливает вид (проверить, что при повторном заходе в «Проекты» показывается сетка, а не последний открытый кейс — если не оговорено иное, начальное состояние раздела при каждом заходе — grid view).
